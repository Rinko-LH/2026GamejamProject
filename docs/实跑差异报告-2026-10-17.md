## 差异清单（按严重度）

### P1 · 画笔和画板在房间里完全不可见 —— 破坏「找画笔」玩法前提
- `BrushPickup` 与 `DrawingBoard` 的 SpriteRenderer **sprite 均为 NULL**（enabled=True 但无图可渲染）。
- 挂在两者上的 `InteractionHint`：markerSprite=NULL（无提示块），highlightTargets 就是那个无 sprite 的渲染器——呼吸高亮也 tint 不到任何像素。
- 后果：交互功能全部正常（E 链实测通过），但玩家**看不见任何交互目标**，只能凭坐标盲按；策划案 4.1「找画笔」的视觉引导为零。
- 根因：旧 RoomShapes 程序化精灵被删（美术改手绘透视）后的遗留空洞——房间 7 张占位图还在，两个关键交互物没人补占位。
- 建议：哪怕先给纯色 1×1 占位块（RoomShapes.Rect 思路回归）或拖两张占位 PNG；同时给 InteractionHint.markerSprite 补「按 E」提示图（D7 三张图之一）。

### P2 · 猫打乱是空转的 —— 代码注释与实现不符
- `CatController` 类注释写明「收拾系统（S3 TidySpot）监听该计数变化自行重置归位状态」，**TidySpot 实际没有任何订阅**。
- 实测：收拾完成后（物品隐藏 + canInteract=false），猫打乱（自然 3 次 + 强制触发）物品不复位、不可再交互。
- 现状：猫打乱 = 冲刺动画 + TaskHints 里一行「CatMischief」，对游戏世界零影响。D12「完整行为版」只完成一半。
- 建议：TidySpot 订阅 `Services.Progress.QuestCompleted`，收到 CatMischief 时 `ResetForNewRun()` 同款复位（_armed=false、物品复显、canInteract=true）。

### P3 · R 重开后「支线进展」面板不清空
- `TaskHints._done` 未实现 IResettable，ResetRun 的遍历够不到它。
- 实测：R 重开 → 进度计数 ALL-ZERO，但左下角仍列着上一局 CatMischief/Water/Breakfast/TidyDesk，且新局上报继续追加。CP-1 只验了计数清零，没验 UI 列表。
- 建议：TaskHints 实现 `IResettable`（_done.Clear() + 文案复位），自动接入 ResetRun。

### P4 · 脏会话中猫打乱上报出现过 1 次 4>3（未能复现）
- 用户遗留会话（连续运行 195s、中途接入）：tracker=4 而 `_mischiefCount=3。
- 干净会话复测：自然触发 + 反射强制 4 轮，严格 3 次封顶，**上限逻辑本身正确**。
- 判断：该会话运行期间发生过未知的对象生命周期扰动（195s 内用户可能有过层级操作/重开菜单），导致 Awake/ResetForNewRun 重跑过一次而未清进度；非稳定复现。
- 建议：维持 R8 纪律（播放态不存盘、不跑装配菜单）；P1-P3 修完后复测一局观察。

### P5 · 美术占位现状（预期内，需知晓实际长相）
- 房间 = 7 张「纯白方块」sprite 旋转散放（`Assets/Scenes/Placeholders` 之外的世界仍是旧占位）；相机 orthoSize=5 视野约 14×10，房间只占中间。
- 画板外框/计时条底/填充 9 个 sprite 缺失——**每次进播放刷 9 条 warning**（两个会话共 18 条），是 D7 预留的到位信号，但也说明特写里计时条/外框不可见（只有画布纸色和墨迹）。
- 猫、收拾物、吃喝有占位图，可见。

### P6 · 开场第一句对白永远不显示（订阅时机竞态，本次新发现）
- **实锤**：时间线 t=1.24→3.00 全程 `dlg=True/0 box=False`（第一行在播但对话框不存在），
  t=3.02 才 `dlg=True/1 box=True`——玩家完整错过开场第一句，空屏约 3 秒。
- **根因**：`DialogueBoxUI` 在 **Update** 里惰性订阅 `LineChanged`，而 `GameManager.Start →
  EnterOpening → DialogueManager.Play → NextLine → LineChanged.Invoke(第 0 行)` 发生在 **Start 阶段**；
  所有 Start 先于所有 Update 执行 → 第一行无订阅者 → 直到 3 秒后第二行才首次刷新 UI。
  只影响每局**第一段**对白（之后 `_subscribed` 常驻，提示/收拾/重开对白都正常）。
- **修复建议（二选一）**：① `DialogueBoxUI` 把订阅挪到 `Start`（Start 之间也有顺序问题——
  更稳的是 `Awake` 里订 + Update 里兜底补订）；② `DialogueManager.Play()` 播完第一行后若发现
  无订阅者，下一帧主动重放当前行（`LineChanged?.Invoke(Current)`），与 `EnsureContext` 同款兜底思路。
- 证据：`docs/实跑证据-20261017/03-对话时间线-开场首行丢失.txt`（片段 1）。

### P7 · 结算期不停对白：R 重开会被对白锁住（边缘场景，代码路径推断）
- `EnterSettlement` 不停 `dialogue`。若时钟归零瞬间正播对白（如无笔提示），对白播完前
  dialogue 上下文一直锁输入，而 `DebugRestart(R)` 在 blocked 时**不派发** → 结算界面按 R 无反应，
  须先 Esc 跳过对白才能重开。可恢复，但结算日志里写的「按 R 重开」在该窗口内失效。
- 建议：`EnterSettlement` 里加 `dialogue?.Stop()`（或结算面板自带确认键走 Confirm 豁免）。

### 对话系统观察项（非 bug）
- `DialogueManager.lines` 是 public 数组字段，运行时可被外部改写——留档卫生问题，建议 private + 属性。
- `TidySpot` 播完成台词**没有**「正在播别的就不抢队列」保护（`DrawingBoardInteract.TryEnterPainting` 有）——
  短时间内完成两个收拾点会顶掉前一段台词。当前 canInteract=false 兜底，影响小。
- 对白结束后 body 文本残留在已隐藏的 Text 组件里（不可见），若将来加"无文本直接显框"路径会闪旧文案。

## 环境备注
- 接入时 Unity 处于播放态且已连续运行 195s（时钟 14:14、水分/饱食归零）——用户离开时未退播放；本次收尾已退出播放，场景未存盘（磁盘场景本就干净）。
- 进入播放有约 24s 域重载延迟（manage_editor play 返回≠播放开始），时序断言须放在单次 execute_code 内完成。
- **播放态 hidden-pause（第三会话遇到）**：`Time.time`/`frameCount` 冻结但编辑器 tick 继续（探针文件仍在写）、
  `isPaused` 却报 False——玩家循环被挂起。`manage_editor pause` 连按两次（暂停+恢复）即复原。
  恢复后首帧 deltaTime 巨大，对白会瞬间自动推进完，断言前先让状态落定。
  另：进播放后 Editor.log 确认**无**域重载，冻结非编译引起，机制未明。
- **execute_code 播放态偶发假阴性（第三会话遇到 2 次）**：同一同步调用内触发对白后读
  `box.activeInHierarchy`/`IsBlocked` 得 False，而同一时刻逐 tick 探针记录为 True（游戏行为始终正确）；
  换直接 `dlg.Play()` 复现失败。结论：游戏无此问题，属 MCP 桥接在播放态下的读取假象——
  播放态断言以探针时间线为准，execute_code 单点读取勿轻信。
- 对话专项探针为临时产物，测完已删（`Assets/Editor/DialogueTimelineProbe.cs` + .meta），编译 0 error。
