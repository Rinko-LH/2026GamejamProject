# 系统实施规范（AI 可执行任务卡）

> 本文档是《今天要画画》Game Jam 项目的**系统拆分与实施规范**。每个系统一张任务卡，
> 供单人/单 AI 独立执行：功能边界清晰、接口明确、依赖最小化。
> 跨系统整合步骤见《跨系统整合手册.md》，本文只回答"某个系统自己怎么建"。
>
> 依据：策划案（`docs/策划案全文结构化基线.md`）+ 数值重规划案（`docs/阶段一-变更留档.md` §数值）。
> 当前代码状态：契约层（S0）与数值对齐（S11）已完成，见文末状态表。

## 0. 全局铁律（违反任意一条 = 返工）

| # | 铁律 | 说明 |
|---|------|------|
| R1 | **三级直连** | ①核心域（`RoomDemo` 根：GameManager/PlayerStats/DayTimer/DrawingBoardInteract/ConsumablePickup/BrushPickup/RoomInteractable）内部允许直连；②新域（UI/World/Quest/Mood/Ending）跨域消费一律走 `Services.Xxx`，禁止 `FindObjectOfType` 其他域具体类、禁止互相持引用；③Quest 域内（S3~S6）允许域内直连。 |
| R2 | **Services 判空** | `Services.Stats/Flow/Dialogue/Progress` 在启动帧可能未就绪（GameManager.Awake 才注册），所有消费点必须判空或 `?.`。 |
| R3 | **画作计数单轨** | 画作完成数只走 `Services.Flow.PaintingsCompleted`；`QuestId` 不含 Painting，支线进度不许重复计数画作。 |
| R4 | **统一重置** | 任何有"本局状态"的新组件必须实现 `IResettable.ResetForNewRun()`。R 重开由 GameManager 遍历全场景调用，不要再往 ResetRun 里加特例。 |
| R5 | **文件=类名** | 每个 MonoBehaviour 独立文件且文件名=类名（踩过坑：多类同文件会让场景引用变丢失脚本）。接口/枚举可独立文件。新建 .cs 后必须 `refresh_unity` 并确认 `.meta` 生成。 |
| R6 | **场景只由装配菜单改** | 改场景对象一律进 `DrawingBoardSetup` 的对应节号（见整合手册 §节号分配），不手摆、不用 MCP 直接建运行时对象存盘（退出 play 会丢）。 |
| R7 | **事件驱动+惰性订阅** | 跨对象通信用事件；订阅方用 `_subscribed` 标志 + Update 重试兜底（InputManager/GameManager 可能晚于消费方就绪）。 |
| R8 | **播放前确认编辑器在编辑态** | 跑装配菜单/改场景前，Unity 不能处于播放模式（污染态下 Awake 不跑、存盘存下运行时对象，本次回归实测踩过）。 |

## 2. 已完成系统（只读，勿重复建设）

### S0 契约层 ✅

- **位置**：`Assets/Scripts/Contracts/`，命名空间 `RoomDemo.Contracts`
- **接口**：`IStatSource`（PlayerStats 实现）、`IGameFlow`（GameManager 实现）、`IDialogueService`（DialogueManager 实现）、`IProgressTracker`（ProgressTracker 单例）、`IResettable`
- **定位器**：`Services.Stats/Flow/Dialogue/Progress`，由 GameManager.Awake 注册、OnDestroy 反注册
- **关键口径**：
  - `Flow.PaintingSeconds` = 实际下笔累计（Tick 同源，低落倍率不污染），数据源 `DrawingBoardInteract.PaintingSeconds`
  - `Flow.DayElapsedSeconds` = 当局实际时长（提前结算后即专注占比分母）
  - `Stats.Add(StatKind, delta)` = 支线恢复状态唯一入口
  - `Stats.IsLowMood`（任一 <20%，带 LowMoodChanged 边缘触发）/ `Stats.AllCritical`（三项 <10%）
- **禁止**：新增重复枚举（StatKind/GameFlowState/DialogueLine/StatChannel 一律用核心域既有类型）；QuestId 增加 Painting 成员

### S11 数值配置 ✅

- **代码默认值**：`PlayerStats`（衰减 0.35/0.30/0.30，倍率 ×0.5/×1.5，阈值 20/20/20，初值 50/20/50）、`DrawingCanvas.paintingSeconds=60`
- **场景序列化值**：装配菜单第 1.5 节显式写死（公开字段改代码默认值**不会**更新场景旧值，这是本次实测的坑）
- **派生规则**：低落时单幅 90s（S7 实现）；一局 480s ↔ 960 游戏分钟（1 游戏分钟 = 0.5 真实秒）；提前结算占比分母 = `Flow.DayElapsedSeconds`
- **禁止**：在任何系统里硬编码新数值（改数值只改 PlayerStats 默认值 + 装配菜单 1.5 节 + 本文档）

- **接口**：`BrushPickup` 已带 `reportId=BrushFound` + `IResettable`（归还已通）；书架触发点在 S3 域内直连 BrushPickup 允许（R1③）。

  2. 拾取链已通（brush.Interact → GiveBrush + Report），只需补触发点；

### S7 低落·机制侧（策划案 5.4）

- **功能边界**：只改**画画耗时**一个乘数：低落（`Services.Stats.IsLowMood`）时单幅 60s → 90s。实现在 `DrawingCanvas.Tick` 内部消化倍率（契约 5 条修正⑤：倍率内化，避免 S7/S8 改同一行）。
- **不做**：移速、去饱和、气泡（S8）；结局判定（S9）。
- **接口**：`DrawingCanvas` 内部读取 `Services.Stats?.IsLowMood`（Tick 内每帧或缓存 + `LowMoodChanged` 刷新缓存）。**`PaintingSeconds` 口径不变**（DBI 累计的是原始 dt，不受倍率污染——契约明文）。
- **依赖**：S0；S11（60/90 数值）。
- **实施步骤**：
  1. `DrawingCanvas` 加 `float _lowMoodScale` 缓存（默认 1.5f）+ 订阅 `Services.Stats.LowMoodChanged`（惰性）；
  2. Tick 内：`ElapsedSeconds += dt * (IsLowMood ? 1.5f : 1f)`——即达标线仍是 60s 但涨得慢；**或**等效实现为"低落时目标 90s"，二选一全项目只许一种，选前者（进度条语义不变）；
  3. 不动 `Tick(float dt)` 签名与调用点（DBI 已传原始 dt）。
- **装配**：无新节（改既有 DrawingCanvas）。
- **验收**：低落时单幅确实变慢（1.5×）；非低落 60s 达标（已通）；`Flow.PaintingSeconds` 统计不受影响（口径=原始 dt）。
- **禁止**：在 DBI 调用点乘倍率（契约⑤）；改 `paintingSeconds` 字段值表达低落（会污染装配菜单案值）。

### S8 低落·表现侧（策划案 5.4）

- **功能边界**：低落三表现的另两个 + 气泡：①移速 -20%（消费方是玩家移动脚本，S8 提供倍率查询）；②全屏去饱和（uGUI 灰度 Image 淡入淡出，URP 2D 无 Volume 后处理——本次已确证）；③低落气泡（画框旁色块占位，素材后期换）。
- **不做**：机制数值（S7）；结局（S9）。
- **接口**：`MoodFeedback`（新类，`RoomDemo.Mood`）订阅 `Services.Stats.LowMoodChanged`；移速倍率通过 `Services.Stats.IsLowMood` 由移动脚本自查（S8 只提供文档约定 0.8，不改移动脚本——若移动脚本不在必保范围则跳过移速项）。
- **依赖**：S0；S1（uGUI 画布挂全屏 Image；若 S1 未就绪可先挂 IMGUI 占位但要在 CP-Mood 换）。
- **实施步骤**：
  1. `RoomDemo.Mood/MoodFeedback.cs`：订阅 LowMoodChanged → 灰度 Image 透明度 0↔0.55 淡入淡出（1s）；
  2. 气泡：玩家附近/画框上的小色块 + 文字（"好累……"占位），同样跟着 LowMoodChanged；
